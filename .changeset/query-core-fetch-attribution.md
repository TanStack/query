Expose cache-wide fetch acceptance and tracked query-function invocation positions. Integrations can reserve positions for direct writes and read operation-local positions from cache events, query-function contexts, and observer results. `fetchSourceStarted` reports an invocation even when a custom persister or behavior ignores its result. Cached data has a `dataSourceSequence` only when Query Core controls the path from query function to result; it is the fetch's first invocation and a lower bound when the fetch retries. Opaque custom persisters and replaced fetch functions leave it undefined.

If behavior setup invokes `queryFn` and then fails, the source event carries a rejected setup-failure promise without a `fetchStarted` event, because no fetch was installed. The Query publishes a terminal error to observers and QueryCache callbacks, except for silent or reverting cancellations. Invalidation and state writes during setup still allow that error; data written during setup remains cached. Reset, a newer fetch, or cache removal retires the failed attempt. Quiet cancellations settle the fetching state, and a reverted cancellation with cached data resolves with that data. A silently cancelled fetch follows the promise of the attempt that directly replaced it, including when replacement setup fails. Query Core observes abandoned eager query-function promises before aborting them, while the returned promises remain unchanged for the behavior. Immutable behavior contexts still allow query-function invocation and source attribution.

Ordinary `context.options` writes reach the Query's options, and stable `queryFn` reads through writable data properties or configurable accessors return a tracked wrapper. Reflective reads of frozen or nonconfigurable descriptors, and accessors that replace their own descriptor while being read, are outside that attribution guarantee. A function captured outside that context can run without a source position. Reset or cache removal before retryer installation retires the fetch, rejects its promise, and reports cancellation. A previously invoked eager source remains observable with a rejected promise. `Query.fetch` continues returning a promise if a cancellation listener throws. Cache removal announces the old Query before a cancellation listener can add a replacement under the same key. The broadcast client also replays the current replacement when an earlier removal listener adds it, so a receiving cache retains that replacement.
