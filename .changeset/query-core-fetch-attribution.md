Expose cache-wide fetch acceptance and tracked query-function invocation positions. Integrations can reserve positions for direct writes and read operation-local positions from cache events, query-function contexts, and observer results. `fetchSourceStarted` reports an invocation even when a custom persister or behavior ignores its result. If behavior setup invokes `queryFn` and then fails, the source event carries a rejected setup-failure promise without a `fetchStarted` event, because no fetch was installed. Cached data has a `dataSourceSequence` only when Query Core controls the path from query function to result; it is the fetch's first invocation and a lower bound when the fetch retries. Opaque custom persisters and replaced fetch functions leave it undefined. Ordinary `context.options` writes reach the Query's options, and stable `queryFn` reads through writable data properties or configurable accessors return a tracked wrapper. Reflective reads of frozen or nonconfigurable descriptors, and accessors that replace their own descriptor while being read, are outside that attribution guarantee. A function captured outside that context can run without a source position.
